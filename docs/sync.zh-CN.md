# Pi Web 里的消息同步

Pi Web 和 `pi` 终端命令行操作的是**同一批**会话文件。你可以在终端开始一段对话，然后在浏览器里继续阅读或往下聊，反过来也一样。本文说明两端是如何保持同步的、哪些内容会自动刷新，以及唯一需要避免的场景。

## 一个会话，两个窗口

一个 pi 会话保存在单个文件里：

```text
~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<uuid>.jsonl
```

终端 `pi` 和 Pi Web 读写的都是这同一个文件。数据不会被复制或产生副本——终端写入一条新消息时，它就落在 Pi Web 正在展示的那个文件里。**你的数据不会丢失，始终都在文件中。**

由于 Pi Web 和终端是两个独立的程序，它们不共享实时内存。Pi Web 把当前对话保存在浏览器里，并在下面这些时机从文件重新加载。

## 哪些内容会自动刷新

Pi Web 会在两种情况下从磁盘刷新：

- **标签页重新获得焦点时**——你在终端干完活切回浏览器，视图会立刻跟上。
- **低频后台轮询**——标签页可见时，Pi Web 每 15～20 秒检查一次是否有变化，所以开着的标签页也会自己跟上。

后台（隐藏）标签页保持安静，避免浪费资源；你切回去的一刻它就会刷新。

刷新开销很小。重新加载对话前，Pi Web 会先做一次极轻量的文件修改时间检查，只有文件确实变了才做完整重载，所以没变化的会话不会闪烁，也不会做无谓的重载。

以下视图都遵循这一行为：

| 视图 | 刷新时机 |
| --- | --- |
| 聊天消息 | 焦点 + 约 15 秒轮询（仅在文件变化时重载） |
| Git 审查面板 | 焦点 + 约 20 秒轮询，以及每次 agent 运行结束后 |
| 文件浏览器目录树 | 焦点 + 约 20 秒轮询，以及每次 agent 运行结束后 |
| 打开文件的 diff | 焦点 + 约 20 秒轮询，以及每次 agent 运行结束后 |
| 会话列表（侧边栏） | 焦点 + 约 20 秒轮询——终端里新建的会话会出现在这里 |
| 打开的文件正文 | 实时——通过文件监听即时更新 |

文件**正文**查看器比较特殊：它直接监听文件，并显示一个小小的 **live** 指示灯，所以保存的改动会立即出现，无需等待轮询。

## 终端干完活后再从浏览器发消息

当你从 Pi Web 发送一条消息时，它会先检查自上次写入以来会话文件是否在磁盘上发生了变化。如果这期间终端追加了消息，Pi Web 会先把它们加载进来，再把你的新消息接到对话真正的末尾。

这可以避免一个隐蔽的问题：如果没有这个检查，浏览器里的新消息可能接到旧的位置上，把对话分裂成两个分支，让终端的消息看起来「丢了」——尽管它们其实还在文件里。

## 唯一需要避免的场景

pi 会话文件的设计是**同一时间只允许一个写入者**。上面的同步行为覆盖了最常见的用法：

> 在一边干活，然后切到另一边。

但它**不能**保证在终端和浏览器**同一时刻**向同一个会话发送消息是安全的。如果两边在同一瞬间写入，对话仍可能分裂成分支。对于同一个会话，请保持同一时间只在一边活跃。两边来回切换是无缝的，但同时写入不是。

## 失败的请求会显示出来

如果模型或供应商的请求失败（例如鉴权错误或请求参数错误），Pi Web 会在该轮对话上显示一个红色的 **Request failed** 横幅并附带错误详情，而不是悄无声息地什么都不显示。这样你能清楚地看到这一轮失败了、为什么失败，从而修正原因（比如 API key 或模型设置）后重试。

## 常见问题

**我在终端改了东西，但浏览器还显示旧对话。**
点一下浏览器标签页（焦点刷新），或等下一次后台轮询。如果还是滞后，可能是会话正在另一边运行——等当前这一轮结束即可。

**Git 面板或文件树看起来不是最新的。**
它会在获得焦点时、可见时每约 20 秒、以及每次 agent 运行结束后刷新。想立刻更新可以用面板上的手动刷新按钮。

**会话列表里没有我在终端新建的会话。**
列表会在焦点和后台轮询时刷新。把焦点切回浏览器，或稍等片刻它就会出现。

**我在终端发的一条消息，浏览器里好像不见了。**
它其实还在会话文件里。刷新一下浏览器标签页即可。请避免在同一时间从终端和浏览器向同一个会话发消息，那可能会把对话分裂成分支。
