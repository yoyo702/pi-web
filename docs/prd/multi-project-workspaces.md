# 多项目工作区 PRD

## 背景与目标

TianForge pi 原本围绕单一 cwd 工作。当用户并行处理多个仓库时，需要频繁切换目录，且文件、Session、Agent 和面板状态容易混淆。

目标是提供类似浏览器垂直标签的项目栏，让每个项目拥有独立、可恢复的工作上下文。

## 用户场景

- 同时维护多个代码仓库，并快速切换。
- 一个项目运行 Agent 时，继续在另一个项目工作。
- 刷新页面后恢复上次项目及其面板状态。
- 快速发现哪个项目正在工作、等待审批、失败或完成。

## 已实现范围

### 项目管理

- 打开、关闭、切换和拖动排序项目。
- 项目栏展开与图标化收起，状态持久化。
- 自定义项目名称、固定或取消固定。
- 关闭后 6 秒内撤销，支持 `Cmd/Ctrl + Shift + T`。
- 关闭运行中 Terminal 的项目时先确认，但不强制停止进程。

### 快速访问

- `Cmd/Ctrl + 1…9` 切换项目，9 表示最后一个项目。
- `Cmd/Ctrl + Shift + [` / `]` 前后切换。
- `Cmd/Ctrl + Shift + P` 打开项目搜索。
- 按名称、路径或 Git 分支搜索项目。
- 最近打开项目进入目录选择器。

### 项目状态

状态优先级为：等待审批 > 失败 > 工作中 > 已完成 > 空闲。

- 橙色：等待审批或用户处理。
- 红色：任务失败。
- 绿色：正在运行。
- 蓝色：刚刚完成。
- 灰色：空闲，不额外显示角标。

项目角标可查看状态数量；顶部状态中心汇总所有非空闲项目。

### 独立恢复

每个项目分别保存中央工作区标签和右侧面板状态。项目切换前同步持久化，防止快速切换造成状态串写。

- 最近会话快照保存在内存和 IndexedDB，切回项目时先立即恢复，再与服务端校准。
- 应用级 SSE 持续接收其他项目的运行状态和完整消息事件，不要求同时挂载所有聊天组件。
- 恢复或切换工作区时重新验证 cwd 授权；服务端重启后项目栏轮询也会自动恢复授权。
- 项目路径支持一键复制；常驻项目不再依赖旧的单工作区切换器。

## 关键规则

- 项目身份使用解析后的 `projectRoot`，同一 Git 仓库的 worktree 归入同一项目。
- `cwd` 表示项目当前实际工作目录，可以是主仓库或 worktree。
- 固定项目始终位于非固定项目之前。
- 项目关闭只移除 UI 工作区，不默认停止后台进程。
- Terminal 只能可靠识别运行、结束和失败；不得通过关键词猜测审批状态。

## 验收标准

- 两个项目之间切换时，Session、文件标签和右侧面板互不污染。
- 刷新后恢复最后活动项目。
- 收起项目栏后仍能通过图标和状态角标识别项目。
- 菜单、搜索、重命名弹窗支持 Esc 或点击外部关闭。
- 等待审批状态不会被普通运行状态覆盖。
- 在另一个项目运行任务时切换工作区，原任务不中断；切回时先看到缓存内容并完成后台校准。

## 后续计划

- 状态条目直接打开具体 Session/Terminal，而不只切换工作区。
- 项目收藏分组和跨项目搜索。
- 统一 SSE 状态通道，减少周期查询。
- 完成、失败状态支持已读和长期保留。
